## 3. init.rc 挖掘新发现（本机已有 27KB dump，纯离线分析）

**重大新发现：**

1. **`/data/.android` 是车厂自己的开机流程创建的**（`on property:sys.interactive="active"` 段，init.rc:498）：
   ```
   mkdir /data/.android 0777 system system
   export HOME /data
   setprop service.adbec.enable 1
   setprop service.adbusbmuxd.enable 1
   ```
   —— 车厂在开机时**主动启用 adbec 与 adbusbmuxd 两个服务**（定义应在 import 的 rc 里）——我们的 rootd/mp.sh 恰好就住在它创建的目录里；且说明这两个服务是**开机常驻的 root 服务**（持久化钩子的天然候选）。
2. root 服务候选（均在主 init.rc 可见）：
   - `service kernel_log /system/bin/kernellog` —— class main，**无 user= 即 root，每次开机必启**。
   - `service sshd /system/bin/start-ssh` —— class main、**disabled**（root 身份）——若可被 ctl.start 触发且配置可控 → 常驻 root shell。
   - `service console /system/bin/sh` —— **user root**，但触发被注释（`ro.debuggable=1` 分支被注释掉）。
   - `service adbd /sbin/adbd --root_seclabel=u:r:su:s0`。
3. **`/sbin/modprobe` 方向排除**：开机默认值 `/sbin/modprobe`，但（a）该文件在设备上不存在；（b）`/sbin` 属 ramdisk（ramfs），运行时写入**不跨重启**。→ modprobe 劫持只能作为运行时入口，不可能借它持久化。
4. **import 文件未在 dump 中**：`/init.environ.rc`、`/init.usb.rc`、`/init.${ro.hardware}.rc` —— adbec/adbusbmuxd/kernellog 的完整定义与触发可能在其中 → **下一登车日优先拉取**。

## 4. 持久化向量表（按风险梯度）

| # | 向量 | 原理 | 验证项（上车日） | 风险/回退 |
|---|------|------|------------------|-----------|
| V0 | **watchdog + fire（已交付）** | PC 在场即自愈 | 无需 | 零风险 |
| V1 | **usbmuxd wrapper** | 车厂 `service.adbusbmuxd.enable=1` 开机的 root 服务；若二进制在 /system（可写），替换/包装为自启钩子（先跑我们的脚本再 exec 原实现） | ① 拉 `/init.usb.rc` 等找服务定义 ② `ls -la /system/bin/usbmuxd`（文件类型/大小）③ `strings` 观察行为 | 中：损坏 usbmuxd 即断 CarPlay USB 通道——须先备份 `xxx.real` 且保留 adb 回退 |
| V2 | **kernellog wrapper** | `/system/bin/kernellog` 每次开机以 root 启动；若是脚本→追加几行；若 ELF→wrapper 换名 | ① `head -c 64 /system/bin/kernellog \| xxd`（脚本=?ELF?）② 运行频率/日志影响（应有 onrestart） | 中低：日志服务失效影响小；备份可回退 |
| V3 | **start-ssh 调查** | class main disabled 的 root ssh 服务 | ① `file /system/bin/start-ssh` ② 找其配置（/system/etc/…）③ 测试 `setprop ctl.start sshd` 是否被拒 | 低：不启用则无变化 |
| V4 | **setprop/ctl 权限测试** | SELinux 关闭的 ROM 上，shell 用户可能能写 `ctl.start`/`service.*` 属性 → **非 root 触发 root 服务** | `adb shell setprop ctl.start sshd; busybox ps \| grep sshd` | 零（只读验证） |
| V5 | **ADB_CONFIG 投放** | adb-ec 服务器（root，每秒 kill+fork 循环）按序读 `/tmp`、`/dev/shm`、`/mnt/shm` 的 ADB_CONFIG（JSON，规则含 "usb:%d:%d"/"filter file="） | ① `ls -ld /tmp`（是 tmpfs 还是到 /data 的软链？决定持久性）② 投放样例 JSON 观察日志行为 | 低-中：明确是"引导车厂服务行为"的通道 |
| V6 | install-recovery.sh / flash_recovery | 经典 Android 开机钩子 | 主 init.rc 未见；拉 import 文件后再确认 | — |

**风险纪律**（沿用项目总约束：不刷机、不改分区）：全部向量都是**文件级**改动 + 原文件备份（`.orig` 命名）+ 单变量测试；任何一步失败都可用 adb 侧恢复。**不在无恢复包的设备上动 boot 镜像。**
