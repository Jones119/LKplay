## 11. 有线 CarPlay 验证实验日志（2026-10-06）

1. 拔电脑线 → iPhone 插车机 USB 口（彼时"USB调试"开）：**无充电、无枚举**——因为调试开启时该口被锁定为"从设备模式"（`dumpsys usb`：mConnected=false / Kernel DISCONNECTED，等电脑接入）。
2. 用户关闭"USB调试"（恢复正常状态）后：**充电恢复** ✓ —— 端口回到主机模式，VBUS 输出正常。
3. 仍**无"要信任此电脑"弹窗**。判断：该 iPhone 此前已与车机完成过配对（车内 `/data/local/tmp/lockdown/` 有 6 条 iPhone 配对记录，最新一条 2026-09-20，序列号与该机一致）；已配对的 iPhone 不重复弹窗。（用户补充：该 9-20 记录可能源自其此前使用 CarPlay 盒子的时期，来源待考，不影响"曾完成配对"的事实。）
4. **重要操作事实**：车机"USB调试"开关 = 该 USB 口的模式总闸：
   - 开 = 从设备模式 + adbd 运行（USB/Wi-Fi adb 可用；但口不能接 iPhone，插入无电不识别）
   - 关 = 主机模式（可接 iPhone/U盘，充电正常；但 adbd 停止，**adb 通道（含 Wi-Fi）全部断开**）
   - 推论：默认状态下"主机模式 ↔ adb 观察"互斥；后续若要观察 iPhone 实插状态，需另找观察通道（第二 USB 口 / 应用层探针 / 或利用持久化记录回查）。
5. 车机内置 `/system/bin/usbmuxd` 为 **root 常驻**（固件集成，非第三方安装）——对 CarPlay 接收端方案是重要资产。
6. 待补测：iPhone 插拔时配对记录是否出现新时间戳（需 adb 恢复后回查）；内核 USB-NCM（cdc_ncm）驱动支持情况。

## 12. 实验日志 III：USB2 口 + iPhone 实机枚举 + usbmuxd 通路实测（2026-10-06）

### 12.1 iPhone 实机枚举（USB2 口）✅
- 条件：调试口开着（从设备模式、未插电脑）时，iPhone 插 **USB2 口**被正常枚举：
  `2-1.4: 05ac:12a8 ("iPhone", Apple Inc.)`，高速 480 Mbps，`bConfigurationValue=4`，3 个接口：
  - `4.0` = 类 `06/01/01`（PTP 静像，无驱动绑定）
  - `4.1` = 类 `ff/fe/02`（Apple 专有 AMDevice/iAP2）→ **绑定 usbfs**（被车内 root usbmuxd 持有）
  - `4.2` = 类 `ff/fd/01`（Apple 专有，无驱动绑定）
- `dumpsys usb` Host State 同时列出 Apple 设备与 ZTE 模块；`ecarx_usbcheck` 日志识别到该机（序列号与 2026-09-20 配对记录一致）。
- **结论：两个 USB 口角色互相独立** —— 调试口锁死为从设备时，USB2 口仍是完整主机 → **有线 CarPlay 硬件前提 ✅**；"调试开 + USB2 插手机 + Wi-Fi adb" = 可全程观测的黄金配置。

### 12.2 系统 usbmuxd 通路实测（软件路线核心发现）
- 常驻：`/system/bin/start_usbmuxd.sh`（while true 看护）+ root 进程；pid 文件 `/data/local/tmp/usbmuxd.pid`。
- **抽象 socket：`@com.carbit.usbmuxd`**（`/proc/net/unix` 实测）。
- PC 侧经 `adb forward tcp:27015 localabstract:com.carbit.usbmuxd` + Python 直连实测：

  | 请求 | 结果 |
  | --- | --- |
  | `ListDevices` | ✅ 返回 `DeviceID:1 / USB / 480000000 / ProductID:4776 / SerialNumber=<与 9-20 同号>` |
  | `ReadPairRecord` | ✅ 有 plist 响应（内容未落盘） |
  | `Connect(62078)` | ❌ Result=3 |
  | `Connect(32498 = swap16(62078))` | ✅ Result=0（打开成功） |
  | `Connect(20480 = swap16(80))` | ❌ Result=3（对端无监听） |

  - **端口号需 16 位字节序互换（swap16）**——该 fork 的私有约定。
  - 打开成功后发 lockdown `GetValue`：连接**立即 EOF**（无响应）→ daemon 对 lockdownd 连接疑有接管/鉴权逻辑，**待离线逆向**（二进制已在手）。
- 二进制字符串证据（待 IDA 深挖）：内嵌 lockdownd 客户端（`com.apple.mobile.lockdown`、`request_pair`、`StartSession`、`ValidatePair`、SSL 握手）；`imux_auth`（`user trusted this computer... pairing now`、`REQ_PAIR_STATUS`）；端口过滤机制（`[tbox] InitFilterList`、`filter file=%s`、`ports.rules`）。
- 其他服务/工具：`init.svc`: adbd / adbec / adbusbmuxd / dhcpcd_usb0 / ecarx_usbcheck；adbd 在 `/sbin/adbd`；ecarx_usbcheck 用 libusbhost 做 USB 黑名单检查（`checkSubUsbBlackDevice`）。
- 工件（已归档 `_artifacts/cs11_bins/`）：
  - `usbmuxd` 2,153,976 B · sha256 `0aa35afcd8f9a87a71179ac4748ce8217b09ed5d0346aad4815685110a9e3e74`
  - `start_usbmuxd.sh` 116 B · sha256 `c7a9a5c16bb6ec546a36467eb2c66a5622b8654e6d3d6ddeb293aa59c5bde022`
  - `ecarx_usbcheck` 5,360 B · sha256 `5db1056b85cdee5f9752472abe28ff88a86c26020df764dd36794940664c370f`
  - `adb`（车机侧工具）109,008 B · sha256 `84bde57c452a68972d9209c5dbe461c587e8776ac527f185a436cb0ebe477af8`
