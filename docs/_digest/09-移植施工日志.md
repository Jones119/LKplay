### 构建排障 #1（2026-10-06）
- 症状：`gradlew help / assembleDebug` 卡死（>7 分钟无进展，超时两次）
- 根因：`gradle/gradle-daemon-jvm.properties` 锁定 daemon=**JDK 25** → Gradle 经 foojay 下载 JDK25（约 200MB；实测 ~50KB/s），且两次运行争抢同一把下载锁 → `LockTimeoutException`（日志实锤）
- 修复（提交 `915070b`）：删除该 daemon-JVM 锁文件 → daemon 改用本机 JDK 21；`gradle.properties` 增加 `org.gradle.java.installations.auto-download=false`；清理卡死的下载进程（WINPID 25712）与 `.part` 残件
- 备注：Gradle 9.5 发行版与 AGP 依赖均走国内镜像（腾讯/aliyun），网络本身无问题
- 复跑验证：构建 #2 daemon 日志确认 `javaHome=JDK21` 正常执行（14:32 启动），修复生效
- 构建 #2 结果：**配置阶段失败** —— `:common` 启用 core library desugaring 但未启用 multidex（AGP 硬性检查："In order to use core library desugaring, please enable multidex."）。修复：`:common`/`:shared` 的 defaultConfig 各加 `multiDexEnabled = true`；`--dry-run` 配置校验通过（45s，全任务图列出）→ 构建 #3 启动
- 构建 #3 结果：**实质编译错误第一批** —— `:shared:compileDebugKotlin` 失败，11 个错误全部为 `Unresolved reference 'RequiresApi'`（3 个文件）。根因：上游 `shared` 依赖 `androidx.car.app:app` 传递带入 `androidx.annotation`，首轮移除 car.app 后断链。修复：`libs.versions.toml` 新增 `annotation 1.9.1` + `:shared` 显式 `implementation libs.androidx.annotation`（核查确认 shared 仅此一处 androidx 依赖缺口）→ 构建 #4 启动
