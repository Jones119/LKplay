## 1. 720p 限制的真相与解除方式

限制**不在应用** ✗，而是车机的一个**逻辑分辨率断言** ✓：

```
Physical size: 1920x1080          ← 面板本来就 1080p
Override size: 1280x720           ← 这就是"720p 限制"（wms 的 override）
Physical density: 160
```

解除（车机侧两条 ✓）：
```powershell
adb shell wm size 1920x1080     # 覆盖值等于物理值 ⇒ 系统直接清掉 override（此后 wm size 不再打印 Override size）
adb shell wm density 240        # 1920/240 == 1280/160 ⇒ dp 空间不变、布局不变，只把像素翻倍
```

**持久化**（"长期保持" ✓，这两项**重启后仍生效** ✓✓）：
- 尺寸：三个命名空间的 `display_size` 都是 **null** ✓ ⇒ 无断言 = 原生 1920x1080 ✓；
- 密度：`settings global display_density_forced = **240**` ✓（这就是 `wm density` 的存储位置 ✓）。

**效果实证**（在车机上取到 ✓）：
- SurfaceFlinger：CarPlay 图层 `size=(1920,1010) crop=(0,0,1920,1010) tr=[1.00,0.00][0.00,1.00]` ✓
  ⇒ **1:1 合成、零缩放** ✓（1920x1010 = 1080 减去车机自己 70px 的栏 ✓）；
- `dumpsys display`：`mOverrideDisplayInfo … app 1920 x 1080 … density 240` ✓；
- 截图：**原生 1920x1080** ✓（归档 `_artifacts/cs11_port/shots/20261010-carplay-1080p-no-override.png` ✓）。

**回退**（若要回到原状 ✓）：
```powershell
adb shell wm size 1280x720 ; adb shell wm density reset
```

## 3. 车机侧调优脚本（`tools/cs11_1080p60_tune.sh`）

内容（**都是 /sys、/proc 项，重启即失效** ✗，需每次开机重放 ✓）：
| 项 | 原值 → 目标 | 理由 |
|---|---|---|
| `galcore initgpu3DMinClock` | 1 → 3 | 不让 GPU 3D 时钟掉到最低档，消合成抖动 |
| `vm.swappiness` | 60 → 10 | 减少换页抖动 |
| `vm.dirty_ratio` / `dirty_background_ratio` | 20/5 → 10/3 | 减小 eMMC 回写卡帧窗口 |
| `mmcblk2` 调度 / readahead | noop / 128 → deadline / 2048 | 更可预测的 IO 延迟（eMMC 是 `mmcblk2`，不是 mmcblk0） |
| 四核 online + `performance` | 已是最优 | 只是确保不被关核 |

**执行方式**：通过 `/data/.android/rootd.sh` 的全能力 root 队列 ✓（把脚本拷成 `/data/.android/rootcmd.sh` ✓，1 秒内执行 ✓，输出在 `/data/.android/rootout.txt` ✓）。
