# 38 · 仪表投屏（媒体 + 导航）实测与下一步

> ⚠️ **2026-10-09 更正（重要，先读这段再读 §2）**：本文的**观察**全部成立（媒体曲名/歌手/专辑/进度 ✓、封面仅第一首 ✓、导航仅路名 ✓、箭头/距离/ETA ✗），
> 但 §2 的**两处原因判断已被字节码级审计推翻**，请勿照抄：
> 1. **"我们已确认调用发出 ✓"是错的**——日志里的 `-> null` 在"**没找到方法**"时也是这个形状（void 成功同样是 null）。
>    真实原因：反射分发器用 `parameter.isAssignableFrom(argClass)` 匹配，而 `int.class.isAssignableFrom(Integer.class)` **恒为 false**，
>    所以 `updateDistanceToNextGuidancePoint` / `updateDistanceToDestination` / `updateETA` / `updateTurnByTurnArrow(int)` / `updateCurrentSourceType` / `updateCurrentProgress`
>    **一次都没执行**（详见 46 号 G1/G8，以及本文顶部那串 10-08 原始日志）。
> 2. **"箭头是图片路线"也是错的**——厂商 `updateTurnByTurnArrow(Bitmap)` 是 `return-void` 空方法（46 号 G2），
>    而 HYLink 的 `updateDriveDirectionImage(byte[])` 通向它**自己的 HUD**、不是厂商接口（47 号 §2.3）。正解是 `updateTurnByTurnArrow(int)` + 厂商 id 表。
> 3. §2 提出的"下一步配方 = `INavigationDI.turnByTurn(Turn)` 整体对象"**仍有效但非必需**（列为 46 号 G6，优先级在 G1/G3/G4/G5 之后）。
> 4. §3 的封面诊断（"问题在我们这一侧"）**依然正确**；正解见 45 号 G3（身份 + 留存封面状态机）。
> **跨会话完整对照见 [48 号](./48-仪表投屏两次会话对照（10-08实测 vs 10-09审计）.md)。**

## 3. 封面只显示第一首（下一步配方）

**已排除**：车机权限/路径 ✗（它确实读到了我们的文件 ✓，第一首正常 ✓）。
**已确认**：换歌后**我们一次都没有写新封面** ✗（`cluster artwork uri=…` 无输出 ✓）⇒ 问题在我们的**封面管线** ✓。

已加诊断 ✓（`artwork decoded id=… bytes=… current=…` ✓）：下次换歌看这行就能区分
① iOS 没推新封面（id 不变 ✗）；② 推了但我们没附到当前曲目（`current` ≠ `id` ✗）；③ 解码失败（`bytes=null` ✗）。
线索：iAP2 `NowPlayingUpdate` 的 `artworkTransferId` 字段号是 **26** ✓（`CarPlayPlaybackStatus.ARTWORK_TRANSFER_ID` ✓），
我们只在 `nowPlaying.artworkTransferId == id` 时才把它当作当前曲目封面 ✓。
