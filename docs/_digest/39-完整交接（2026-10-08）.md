## 1. 项目是什么

**把一辆领克（Lynk & Co）CS11 车机变成 CarPlay 接收端**：手机上不做任何改装，车机上装我们的
Android 应用 **DiPlay**（本仓库）——**无线 CarPlay 为主**（车机自开热点 + 蓝牙 iAP2 交握 + AirPlay 走 TCP），
有线（USB + MFi）为**已明确放弃**的方向。

- **主仓库**：`D:\Development\DiAuto-DiPlay\CarPlay-CS11`，分支 **`cs11-api19`**（这是 CS11 专用分支）
- **工作区**：`D:\Development\DiAuto-DiPlay`（`docs/` 文档、`tools/` 脚本、`_analysis/` 逆向素材、
  `_artifacts/` 日志与截图、`_upstream/` 上游与盒子固件）
- **应用**：包名 `com.shihab.diplay`（debug 版后缀 `.hudtest`），版本 `0.2.13-cs11.1`，
  这是 **DiPlay 上游（shihabal3amri/DiPlay）的 CS11 适配分支**
- **目标硬件**：领克 CS11 车机 = **i.MX6Q 四核 996MHz / armv7 / Android 4.4.3（API 19）**，
  面板 1920×1080，ROM 逻辑分辨率 `1280x720`、density 160

## 3. 技术链路（一次无线 CarPlay 的完整路径）

```
iPhone →(蓝牙 iAP2 RFCOMM 0x5702/0x5703)→ 车机
       → device 信息(0x4e0d/0x4e0e) → CarPlay 可用性(0x4301) → 下发 Wi-Fi 热点凭据(0x4e0d)
iPhone 连车机热点 →(TCP 7000)→ RTSP 交握 → SETUP 130(iAP 隧道)/110(主屏)/111(仪表)/100-102(音频)
       → 110 流：H.264 → MediaCodec → TextureView
       → 100 流：OPUS（通话/语音）→ 我们自带的 libopus 解码
       → 麦克风：AudioRecord → libopus 编码 → 密封 → UDP 上行
       → 触控：HID 上报（pointerId 分槽）
```
关键常量：显示 uuid `MAIN_UUID`(主屏)/`ALT_UUID`(仪表流 111)；音频类型 `media/speechrecognition/telephony`；
音频格式位掩码里 **必须有 Opus**（见 §6）。

## 4. CS11 的硬约束（**这些决定了一切设计**）

| 事实 | 影响 |
|---|---|
| **Android 4.4 / API 19** | 没有 `AudioRecord.Builder`/`read(…,mode)`、没有 `MediaCodec.setOutputSurface`、没有 `MediaCodecList.getCodecInfos`、没有 `AudioAttributes`、没有 MediaSession —— **全项目大量 compat 层**（`shared/.../compat/Cs11Compat.kt` 等） |
| **没有 Opus 编解码器** | 我们自带 `libdiplay_opus.so`（armeabi-v7a，BSD-3 ✓ 来自 EasyPlay 分析 ✓），`LegacyNativeOpus.kt` 用同名 JNI 类绑定 ✓ |
| **厂商 H.264 解码器有缺陷** | Surface 销毁后**重建的解码器会退化为客户端缓冲**（`OMX_SetParameter() failed for StoreMetaDataInBuffers`）⇒ **画面黑但流是好的** ✓ 对策：Surface 丢失后**重建整个宿主活动**（= 新解码器 ✓）——见 §6 |
| **麦克风被百度语音助手独占** | 唤醒词开着时 `AudioRecord.read` 首帧返回 **-3**；关掉车机"语音唤醒"后 `VOICE_COMMUNICATION` 可用 ✓（HAL 显示 `No active record client` ✓）；**用户已接受**不再改录音键 ✗ |
| **方向盘语音键被车机吞掉** | 厂商键码 `200231` 只被 `XCInputService` `keyCode consumption` ✗、不转发 ✗（音量+=200024、下一首=200087、上一首=200088 **会**转发 ✓）⇒ **用户已决定接受现状** ✓ |
| **车机音量键跟随"当前主音量流"** | `MediaFocusControl: getCurMasterStream` ✓ ⇒ 想让播报时音量走"导航"，必须在**播报期间持有导航流（12）的焦点** ✓（已实现 ✓） |
| **厂商导航用私有流 12** | `STREAM_NAVI_TTS=12`（vendor），提示走它 ✓；车载地图播报要"**图片**"路线（不是 id ✓）——见 §8 |
| 存储是 FUSE 视图 | `/sdcard` 上 `chmod` 不一定生效 ✗，但车机进程实际**能读到**我们的文件 ✓（已验证 ✓） |

## 9. 铁律与踩过的坑（**别再重复**）

1. **无线 CarPlay 必须广播 Opus** ✓ —— 去掉它 iOS 会**完全不建音频流** ✗（试过两次 ✓）。
2. **不能用帧率判断"卡死"** ✗ —— CarPlay 是**脏区域流**，静止时本来就 ~1fps ✓（我曾据此误判并造成"不断重连" ✗，已回退 `1886552` ✓）。
3. **厂商 H.264 解码器重建会坏** ✗（客户端缓冲）⇒ 只能**让 Surface 不销毁或重建活动** ✓。
4. **不要 merge 上游 `origin/main`** ✗（已大幅分叉 ✓）⇒ 按主题人工移植并带上游测试 ✓。
5. **车机 `pm disable` 无效** ✗（返回 0 但不生效 ✗）；强停百度服务会**自启** ✓ ⇒ 需循环 ✓。
6. **`hasSession()` 不可靠** ✗（CarPlay 连着时可能 false ✗）⇒ 判"CarPlay 宿主是否可见"要用宿主活动自己发布的标志 ✓（`DiPlayScreenState` ✓）。
7. **中控地图卡片会盖住 CarPlay** ✗（DiPlay 活动 `onStop` 会排定它 ✓）⇒ 已加抑制 ✓。
8. **`setprop` 重启失效** ✗；**root 链与调优每次开机都要重跑** ✗。
9. **logcat 的 `-s TAG` 过滤在这台车机上不可靠** ✗ ⇒ 把日志 `-d` 落盘再 grep ✓。
10. **冷启动很慢**（multidex ✗）⇒ 启动后等 30~60 秒再判定 ✗。
11. 换歌/切前台时**先看日志再改代码** ✓（本项目的多数正解都是日志里读出来的 ✓）。
12. 遵守用户约束：**不引入第三方重打包 APK** ✗、**仓库不放明文凭据** ✗、**UI 沿用既有实现** ✓、
    用车请**注意油耗，不用 adb 时熄火** ✓。
