## A. ⭐ 仪表投屏（本次主目标）

### A1 开关与绑定（30 秒，先确认"功能真的开着"）
```powershell
adb -s <CAR> logcat -d | Select-String -Pattern "DiPlay-Cluster|DiPlay-Dim" | Select-Object -Last 12
```
- **通过**：出现 `cluster push setting=true property=unset enabled=true`（**这就是"重启后无需 adb"的判据**），随后出现
  `cluster navi interaction=com.ecarx.xui.adaptapi.diminteraction.NaviInteractionImpl` 与 `cluster media interaction=…`。
- **不通过**：只有 `enabled=false` ⇒ 先到 DiPlay 设置里把 **「仪表盘投屏 · 媒体与导航」** 打开。

### A2 ⭐ 导航：数据真的到厂商服务了吗（**首要铁证**）
用 Apple 地图开始一段**有转向指令**的导航（要在行驶或模拟行驶中）。
```powershell
adb -s <CAR> logcat -d | Select-String -Pattern "updateTurnByTurnArrow|updateNextGuidancePointName|updateDistanceToNextGuidancePoint|updateDistanceToDestination|updateETA|NavigationDimInteraction|no matching overload|skipped"
```
- **通过（两条都要）**：
  1. 我们的 trace 五连发，**括号里带 `int`/`String` 签名**：
     `cluster updateTurnByTurnArrow(int) args=[7]` / `updateNextGuidancePointName(String) args=[…]` /
     `updateDistanceToNextGuidancePoint(int) args=[744]` / `updateDistanceToDestination(int) args=[41900]` / `updateETA(int) args=[600]`
  2. 厂商自己的行（tag `NavigationDimInteraction`，3 空格分隔 6 个值）出现且**数值合理**，例如左转：
     `7   思菩兰路   41900   600     744`
- **不通过**：
  - 有 `no matching overload` / `-> skipped` ⇒ **把那一行原样发我**（这是匹配器问题，可控）；
  - 厂商行完全没有 ⇒ 服务没收到（绑定时序/接口问题，把 A1 的输出一起发我）。

### A3 ⭐ 箭头 / 距离 / ETA 的**肉眼判据**（仪表上看）
- **通过**：仪表出现**转向箭头**；目的地距离显示成 `41.9km` 这类；ETA 显示成 `10min` 这类（不是多天数值、不是 `<1min` 卡住不变）；
- **不完整快照时**：宁可不显示，也**不应**再出现恒定的 `0 m` / `<1min`（这是旧版的占位值症状）。

### A4 ⭐ 封面：换歌是否跟得上（3 首以上有封面的歌）
每换一首，抓：
```powershell
adb -s <CAR> logcat -d | Select-String -Pattern "artwork decoded|artwork parked|cluster cover identity|cluster artwork encoded|cluster artwork grants|cluster artwork uri|albumCover2"
```
- **通过（链条完整）**：
  `artwork decoded id=… current=…` → `cluster cover identity=Identity(title=…, artist=…, album=…)`（`published=true`） →
  `cluster artwork encoded bytes=… edge=…` → `cluster artwork grants=N provider=true uri=content://…` →
  厂商 `updateMediaInfo ==== … albumCover2 = content://com.shihab.diplay.hudtest.artwork/covers/<session>/<uuid>.jpg`
  且**每换一首 uuid 必须变**；仪表上封面跟着变。
- **不通过**：
  - `grants=0` 或 `provider=false`，并回退到 `uri=file://…` ⇒ 记下这两行（授权/Provider 问题）；
  - 我们每首都有新 `content://…uuid` 而仪表仍显示默认图 ⇒ **取图侧**问题（把这组行发我）；
  - 全程只有第一首有 `cluster artwork uri=` ⇒ 封面管线仍有问题。

### A5 重推保活（不用换歌）
播放中**静置 30 秒**，然后在仪表上**切走导航页再切回**（或让车机重启一次 DIM 服务）。
- **通过**：静置时每 ~10 s 一行 `cluster repush due title=… playing=… artwork=…`；切回后 **10 秒内**媒体卡片自行恢复（不需要换歌）。
- 若失败：记下"切回后是否出现 `cluster repush`/`cluster media interaction=`"。

### A6 暂停语义
暂停播放。
- **通过**：`cluster cover … published=false` 且 `cluster artwork uri=null`（参照语义：暂停不保留封面）。

### A7 媒体字段回归（应有，非新功能）
曲名 / 歌手 / 专辑 / 播放状态 / 进度在仪表上正常。

### A8 若仪表整体没反应，一次抓这些给我

## B. API-19 越界修复的三项实机判定（顺带，成本低）

### B1 ⭐ F1：`Math.floorDiv` 崩溃是否已消失（**最能暴露的一项**）
**在车机上用 Apple Music 播放**（走 103 缓冲流，是最可能走到 `syncedNtp()` 的路径），播 2–3 分钟。
```powershell
adb -s <CAR> logcat -d | Select-String -Pattern "NoSuchMethodError|java.lang.Math.floorDiv|airplay-ntp-rx|airplay-ntp-tx|Math.floorMod"
```
- **通过**：**完全没有** `NoSuchMethodError: java.lang.Math.floorDiv`（修复前会在这里出现）。
- **不通过**：命中即把整行发我（说明还有别的调用点）。

### B2 F4：中央屏悬浮地图卡是否真的出现了
打开"中央屏地图卡片"（DiPlay 里那个联动开关 + 车机主界面场景）。
```powershell
adb -s <CAR> logcat -d | Select-String -Pattern "DiPlay-CenterMap|card shown|card failed|TYPE_APPLICATION_OVERLAY|type=2002|type=2038"
```
- **通过**：出现 `card shown WxH at x,y` + `card surface …`，且**屏幕上真的看到卡片**。
- 若仍 `card failed` ⇒ 是授权问题（`SYSTEM_ALERT_WINDOW`/ROM 预置），把该行发我。

### B3 Dalvik 容忍度（决定一条重要的代码写法约定）
用一次**真正走到媒体键 + NowPlaying** 的会话（播放音乐 + 按方向盘键）。
```powershell
adb -s <CAR> logcat -d | Select-String -Pattern "NoClassDefFoundError|VerifyError|android.media.session|LocaleManager|UsbConfiguration|media keys active|legacy media key"
```
- **看两件事**：① 有没有 `NoClassDefFoundError`/`VerifyError`；② 是否出现 `media keys active (legacy MEDIA_BUTTON) focusGranted=…`。
- 这决定 doc 46/49 里"守卫化新类型引用在 Dalvik 上到底崩不崩"的悬案。
