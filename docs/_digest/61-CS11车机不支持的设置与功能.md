# 61 - CS11 车机不支持的设置与相关功能（整理）

日期：2026-10-13　适用：领克 CS11（Android 4.4.3 / API19 / i.MX6Q 4×A9 1GHz / 2GB）

**取证方式**：本文每条都标了来源——`代码 file:line`（本仓库实际守卫/注释）、`实车`（本会话在车机上测到的现象）、`文档`（项目内已记录的实测）。**未验证**的会明确写"未验证"，不写成结论。

---

## 1. 四条根本限制（其余条目基本都由它们推出）

| # | 限制 | 证据 | 直接后果 |
|---|---|---|---|
| L1 | **Android 4.4.3 / API19** | `ro.build.version.sdk=19`；代码里 API 守卫统计：`>=21` **31 处**、`>=23` **7 处**、`>=26` 3 处、`>=27` 1 处、`>=29` 4 处、`>=30` 1 处、`>=31` 3 处、`>=33` 3 处 | 凡 API>19 的能力在车机上都必须走降级分支或直接不可用 |
| L2 | **没有 TUN 设备** | 实车：`/proc/misc` 无 `tun`、无 `/dev/tun`；代码注释 `CarPlayHostActivity.kt:1797` 起"the kernel has no TUN driver, so the classic VpnService/NCM bridge cannot attach" | 经典 `VpnService` + NCM 方案无法建立；AirPlay 只能靠**用户态 lwIP 桥**（现已实现）或内核 `cdc_ncm` 网卡（需 root） |
| L3 | **没有 `com.android.vpndialogs`（VPN 确认对话框）** | 代码注释 `CarPlayHostActivity.kt:667`：本车机系统没有该组件，`launch` 会抛 `ActivityNotFoundException`（已有降级：告知用户无法授予 VPN 同意并以"无 VPN"继续） | 任何需要走系统 VPN 的功能都无法获得用户同意 |
| L4 | **没有 HUD（抬头显示）** | 代码注释 `CarPlayHostActivity.kt:2211`：本车唯一"仪表"是方向盘后那块 LCD | 面向 HUD 的功能（如 HUD 导航投射）不存在，只有"仪表盘地图"这类 LCD 方案 |

补充（与 L2/L3 同源）：**root 路径不可交付**——它需要 adb（`/sbin/adb-ec ... ppp` + `persist.adb.tcp.port`），实车测得 app 自己**写不了** `service.adb.*`/`persist.adb.*`（init 属性权限），因此"正常使用（关 USB 调试）"下不可用；该路径已按决定降级为隐藏调试兜底。

## 2. 视频相关

| 设置 / 功能 | CS11 上的状态 | 原因 / 证据 | 现在的替代 |
|---|---|---|---|
| **60 fps**（`frame_rate` → `s_60_fps_smoother_motion`） | **不可用（会掉帧）** | 实车/文档：CS11 只能稳定 **~30 fps** 的 H.264 解码+呈现；请求 60 会让手机发到 ~53 fps / ~9.5 Mbps，管线追不上、过期帧被丢（`AirPlayPersistence.kt:473-474`） | 默认 30 fps；60 fps 项保留但实际会退化 |
| **HEVC / H.265 高效视频**（`efficient_video`、`hevc_h_265_video_transport`） | **默认关闭** | 代码注释：**本机 vendor 解码器无法在 surface 模式下重建**（`CarPlayHostActivity.kt:487`、`:775`）；另有 `hevc=false softwareHevc=false` 的启动日志 | 走 H.264；文案本身写着"为了最广的车机兼容性请保持关闭" |
| **自适应画中画分辨率**（`adapt_pip_resolution`） | **不可用** | 依赖 API21+ 的 `MediaCodec` `VideoCapabilities` 探测；4.4 没有（`CarPlayHostActivity.kt:3218` 注释：4.4 只能"确认默认解码器可创建"） | 用固定档位 + 失败回退 |
| 分辨率/画布档位 | **部分档位不可用** | 有专门文案与判据：`canvas_dimensions_unsupported`、`frame_rate_unsupported`（`CarPlayHostActivity.kt:3250-3251`）、`resolution_canvas_unsupported` / `this_head_unit_cannot_use_the_smaller_size_at_this_resolut`（`:3334-3335`） | 自动回退到可用档位并给出说明 |
| 受保护视频（DRM） | **播不了** | 代码：车机播放器无法播放时按 Apple 规范回报，并弹 `video_cannot_play`（`CarPlayVideo.kt:99-105`） | 由 iPhone 侧处理 |

## 3. 音频相关

| 设置 / 功能 | CS11 上的状态 | 原因 / 证据 | 现在的替代 |
|---|---|---|---|
| **Opus 麦克风上行** | **不可用** | 代码注释 `CarPlayHostActivity.kt:3414`：**本机没有 MediaCodec Opus 编码器**，所以麦克风输入只广播 LPCM | 有线只用 LPCM；**并因此踩到 MTU 分片导致微信语音无声**（已修：`MicrophoneFramePolicy`，把 LPCM 帧封顶到 12 ms / 1188 B） |
| **高级音频通道映射**（`advanced_audio_channel_mapping`） | **不可用** | 依赖 API23+ `AudioTrack.Builder`、API21+ `setVolume(float)`、API23+ `write(...,mode)`——均在 4.4 降级（`AudioChannelPreview.kt:67,77,91` 注释） | 4.4 用 `STREAM_MUSIC` + `setStereoVolume` + 3 参阻塞写 |
| 音频焦点接管（`contrib_audio_home_toggle_audio_focus`） | **受车机限制** | 代码注释 `AirPlayPersistence.kt:199`：本车音量键跟随 `getCurMasterStream`（持有音频焦点的流） | 保留开关 + 车机侧行为说明 |

## 4. 无线 / 连接相关

| 设置 / 功能 | CS11 上的状态 | 原因 / 证据 | 现在的替代 |
|---|---|---|---|
| **自动加入热点（实验性）** | **不可用** | 文案自身写明"**适用于 Android 13 及以上**、支持相关固件且仅使用 5 GHz 的车载热点"；并要求 `localhost:5555` 本地 ADB 与已授权（不支持 TLS 无线调试配对） | 需人工在车机设置里开热点；Wi-Fi Direct / 现有 Wi-Fi 是备选 |
| **本地 ADB 自动授权**（`auto_grant_msg`、`btn_permissions_ready`） | **正常使用场景不可用** | 需要本地 ADB（`localhost:5555`）；关 USB 调试后没有 adb | 手动授予；诊断页给出逐项指引 |
| 悬浮窗权限"显示在其他应用上层"（`center_map_overlay_missing`） | **4.4 安装即授予** | 代码注释 `CarHotspotSetup.kt:18`：`canWrite`/`canDrawOverlays` 是 API23+，4.4 上这两项权限安装即授予 | 无需处理；文案里保留 ADB appops 提示仅供其他机型 |
| 内核 `cdc_ncm` 网卡传输 | **需 root + adb ⇒ 不可交付** | 见 §1 补充；`debug.diplay.ncm_legacy=kernel` 保留为隐藏调试兜底 | **用户态 lwIP 桥**（默认） |

## 5. 系统 / 界面能力

| 功能 | CS11 上的状态 | 原因 / 证据 |
|---|---|---|
| `RippleDrawable` 点击水波纹 | 降级为静态底色 | API21+（`DiPlayActivity.kt` 注释"CS11: RippleDrawable 是 API21+；4.4 回退为静态圆角底"） |
| 系统 ActionBar / 主题 | 需手动剥离 | 代码注释 `CarPlayHostActivity.kt:524`：4.4 回退主题会带上旧式标题栏，需显式去掉 |
| 语言设置（`LocaleManager`） | 走旧偏好 | `Api33Locale.kt:12`：`android.app.LocaleManager` 是 API33 类型，按项目约定做版本隔离；4.4 用 `SharedPreferences` |
| 主题模式（深/浅）能力探测 | 受 API 限制 | `ThemeModeDiagnostics` 用版本隔离探测 |
| 仪表盘上的 CarPlay 地图（实验性，`carplay_map_on_instrument_cluster_experimental`） | **存在但属实验性** | 依赖车机 LCD 仪表与车机侧渲染；本会话**未在 CS11 上实测**（未验证） |
| 方向盘按键映射（`wheel_map_zoom`、`wheel_joystick`、`wheel_zoom_behaviour`） | **取决于车机按键上报** | 需要 CS11 自身把方向盘键事件交给应用；**未验证**具体可用键 |

## 7. 已经做出来的"替代方案"（因为平台不支持）

| 平台缺口 | 我们的替代 |
|---|---|
| 无 TUN / 无 VPN 对话框 | **用户态 NCM 桥 + 自带 lwIP 2.2.0 栈**（不依赖 root/adb），失败自动回退内核网卡 |
| 无 Opus 编码器 | 麦克风走 LPCM，并把帧封顶到 MTU 内（修掉微信语音无声） |
| 关 USB 调试后无 logcat | **落盘诊断日志** `/sdcard/DiPlay/logs/`（4 份轮转、崩溃写栈），可事后取回 |
| 无 root 无法持久化传输 | AUTO 优先用户态 + 内核兜底（`debug.diplay.ncm_legacy`） |

## 8. 明确未验证的项（不要当成结论）

1. **Wi-Fi Direct 模式在 CS11 上是否可用**（本会话未测）；
2. **仪表盘 CarPlay 地图（实验性）**在 CS11 上的实际表现；
3. **方向盘按键**（缩放/摇杆/方向）在 CS11 上具体哪些键可上报；
4. **窄屏单栏回退**（`isCompactLayout`）的真机表现（手头只有 1800×2880 平板与 1280×650 车机）；
5. **HEVC 是否在部分片源/档位下可硬解**（当前一律按不可用处理）。
