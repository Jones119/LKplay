# 102 · 拷贝优化第一批：原地解密（2026-10-23 实车）

> 背景：60fps 请求下 `rx` 能到 35–46，`shown` 卡在 25–30、`dropped` 每 5s 30–95。
> 先按"砍拷贝"的最小一刀做实验：把"读进共享 body 数组 → 解密到池化帧"合并成
> "直接读进池化帧 → 原地解密"。

## 1. 改了什么

| 文件 | 改动 |
|---|---|
| `shared/.../airplay/ScreenStream.kt` | 视频帧（sealed）不再读进复用的 `body`，而是 `frames.acquire(bodySize)` 直接读进池化缓冲，再 `chachaOpenInto` **原地**解密（in/out 同一个数组）；新增 `onSealedFrame()`。config/明文帧仍走旧路径 |
| `shared/.../airplay/VideoFramePool.kt` | `OwnedVideoFrame.length` 改为 `var`（`internal set`），因为 sealed 长度要读完后才知道、明文长度解密后才知道 |

每帧少一次 1.3MB（720p）拷贝，少一次缓冲获取。

## 2. 验证

- **单测**：`:shared:testDebugUnitTest :common:testDebugUnitTest --rerun-tasks` → **BUILD SUCCESSFUL**（5m43s）。
- **构建**：`:mobile:assembleStandaloneDebug` 成功，装机成功。
- **实机烟测**（✅ API19 实机）：
  - `video first decrypted frame sealed=3197 plain=3181`（差值正好 16B tag）⇒ 原地解密可用；
  - 30fps 会话稳定：`rx≈29–30 / shown≈29–30 / dropped=0 / queueMax 1–2 / maxGap 73–122ms`；
  - 无 `BadTag`、无 `screen stream ended`。

## 3. 效果（⚠️ A/B 未严格交错，内容/温度未完全控制）

| 场景 | 改前 | 改后 |
|---|---|---|
| 30fps 静态，App CPU | 84–96% | **78–85%**（约 −7 点） |
| 60fps 请求，App CPU | 152% | **150%**（无变化） |
| 60fps 请求，shown/dropped | 25–30 / 30–95 | 24–30 / 6–36（随机波动，未改善） |

结论：**这一刀在 30fps 下省了约 7% 单核，但不足以撬动 60fps**。

## 4. 60fps 的真正墙：按线程看（✅ 实机 `stat` 差值，窗口约 13s，数值按 13s 归一）

| 线程 | ms/s（约） | 说明 |
|---|---|---|
| 主线程（`.diplay.hudtest`） | **~1900** | 4.4 的 HWUI **在 UI 线程上画**：TextureView 的全帧 textured quad 绘制都在这里 |
| `ncm-us-rx` | ~1430 | USB bulk→NTB 解析→JNI→pbuf→lwIP |
| `airplay-audio-r` | ~1180 | LPCM 写 AudioTrack |
| `carplay-video` | ~780 | 解码喂帧循环 |
| `GC` | ~585 | 分配压力仍在 |
| `ncm-us-tx` | ~540 | 1ms 轮询 |
| `CodecLooper`/`MediaCodec_loop` | ~520/~480 | 厂商 OMX 内部 |
| `airplay-screen` | ~420 | socket 读 + 解密 |
| `lwip-tcpip` | ~390 | lwIP 线程 |

⇒ **最大的单点是"UI 线程在画 TextureView"**，不是拷贝、也不是 VPU（空闲纯解码 82–88fps@720p）。

## 5. 下一步（按证据排序）

1. **换渲染承载**：TextureView → SurfaceView（把全帧绘制从 UI 线程挪到 SF/IPU）。历史上有黑屏证据（doc 36/41），但现在的线程数据说明它值这个风险；要做成可回退开关。
2. **codec 输入直写**：把解密目标换成 `getInputBuffers()[i]`（需要 RX↔解码线程的 buffer 环），再省一次 1.3MB 拷贝。
3. **NCM RX native 化**：`ncm-us-rx` 1.4 核里大部分是 NTB 解析 + JNI + pbuf 拷贝。
4. 音频写线程（1.2 核）与 GC（0.6 核）是另外两条独立战线。
