# 13 · Root 可行性评估（三重墙之解 + 社区线索）

> 日期：2026-10-06 ｜ 触发问题：「给车机 root 是否有可能解决：内核无 TUN + 无 root + 网络服务只认自己两口的"三重墙"？」
> 结论：**能**——root 后"三重墙"只剩"半堵"（TUN 那堵可直接绕开）。且已发现**两条社区实证的 root 入口**，其中"su 试探"最优先：可能一行命令得手。

## 1. Root 对三重墙的逐一分析

| 墙 | root 后 | 说明 |
|---|---|---|
| ② 无 root（shell 零能力位） | ✅ 直接解决 | ifconfig / ip / iptables / 任意操作 |
| ③ 系统以太网服务只认 TBox(`2-1.1`)、DVR(`2-1.2`) | ✅ 直接绕过 | 不需要系统服务——root 自己配置网卡（这正是 CarPlay 盒子内部的架构） |
| ① 内核无 TUN | 🔶 **不再需要它** | root 不"造出"TUN，但无需 TUN：内核已有 cdc_ncm 且**已建出 usb1**，直接 `ifconfig usb1 up` + 配 IPv6 链路本地地址即可让媒体走 USB-NCM。若坚持原版 VpnService 设计：可试 tun.ko（需模块支持）或自编译内核（需刷写入口）——均非必需 |

**额外收益**：把 DiPlay 装成系统应用；**全分区备份**（深入操作前的保命步骤）；修日志洪泛/看护崩溃；读 `/data/misc` 等运行时数据；探索 nFore 蓝牙栈（纯无线路线）。

## 2. 社区实证：CS11 老车机的 root 入口

### 2.1 串口（"串口工具"）通道 —— 最优先
和悦网络科技论坛（`lynkco.hyphp.cn`，即 HY Link 开发方，专服务 CS 老车机）帖子 **t/114《串口工具调试命令合集》** 直接给出使用 `su` 的命令（原文引用）：

```
# 一键安装APP（注意 第一句 su 也要复制，我发现很多人没复制！）
su
mkdir /storage/emulated/hy_usb
mount -t vfat /dev/block/sda1 /storage/emulated/hy_usb
pm install -r /storage/emulated/hy_usb/hy.apk

# 开启USB调试（开启后杯架USB1口就无法读取U盘数据了 需要换到 USB2口）
su -c settings put global adb_enabled 1

su -c settings put system FACTORY_USED_AUTHORITY 0
```
附件：`串口精灵_2.0.2.apk`（7.9MB，8258 次下载）。

解读：
- 命令跑在**车机侧 Android shell**（`/dev/block`、`pm install`、`settings` 均为车机）；
- **`su` 无密码直接可用** → 串口通道 = root shell 入口；
- "串口精灵"为**手机 App**（"手机开飞行模式再进"防闪退），配外接硬件使用（用户问"插上不亮灯"→ 有物理适配器）；
- 获取途径：和悦淘宝店 `hyphp.taobao.com` / 论坛 QQ 群（备注车型）。**待弄清：适配器接车机哪个口（服务口/隐藏 UART）**。

### 2.2 其他旁证
- **同代 GKUI 车机有 KingRoot 临时 root 先例**（"长时间断电启动后 root 全部关闭"——漏洞提权典型特征）。⚠️ 不建议此类商业工具（遥测/不可控），仅作"该代平台可提权"佐证。
- E02/E03（联发科）走"深度刷机模式"破解——**SoC 不同，不适用 CS11**。
- 工程模式：领克03 拨号 `#*32279` 可开 ADB（已用通道）；菜单内可能还有更多开关（通电时探索）。
- 社区对 CS11 的定义（t/354）：**CS11=芯片平台名**，车型覆盖 2018-2021 款 02/03/03+ 与 2017-2020 款 01。

### 2.3 软提权窗口（不开盖路线）
- 内核：**Linux 3.10.53+**（`ro.build.kernel.version`: `#1 SMP PREEMPT Thu Jul 16 ... 2020 armv7l`）——版本底座 2014-10，但**构建于 2020-07，NXP/ECARX 可能已回合部分补丁，必须实测**。
- 候选 CVE（若未打补丁，均有公开 ARM PoC）：

| CVE | 内容 | 修复版本（约） | 判定 |
|---|---|---|---|
| CVE-2014-3153 | futex（towelroot） | 3.10.44（2014-06） | 版本号晚于修复 → **很可能已修** |
| CVE-2015-3636 | ping socket UAF（pingpong） | 3.10.76 附近（2015-05） | 可疑 |
| CVE-2016-0728 | keyring 引用计数溢出 | 3.10.97 附近（2016-01） | 可疑 |
| CVE-2016-5195 | Dirty COW | 3.10.104 附近（2016-10） | 可疑 |
| CVE-2016-8655 / CVE-2017-6074 | AF_PACKET race / DCCP double-free | 2016-12 / 2017-02 | 可疑 |

- 前置条件已具备：adb shell（shell uid 可用）；无 root 且 `ro.debuggable=0`；大概率无 SELinux enforcing / 无 KASLR（32 位 ARM 该代）——**全部待实测**。

## 3. 下一步（车机通电后）优先序

1. **`su` 试探**（5 分钟，可能即拿 root）：`adb shell su -c id`（超时保护；存在但拒绝 → pull 分析授权逻辑）。
2. 跑侦察脚本 `tools/cs11_root_recon.sh`（内核/模块/su/SELinux/dmesg 限制/工程设置，全部只读）。
3. 若 su 不可用 → 按 2.3 清单实测内核补丁级别（无害探测 → 必要时编译 ARMv7 PoC）。
4. 若走串口线：联系和悦（淘宝/QQ 群）弄清"串口工具"硬件细节；或自行定位车机调试串口（拆机，后手）。
5. **任何深入操作前：先做全分区备份。**

## 4. 若 root 成功 —— CarPlay 路线升级

- 媒体段：从"Wi-Fi 混合"升级为**内核 NCM 直连**（盒子同款架构：低延迟、无热点切换、无额外配对）。
- 改动量：App 增加"root 模式"attach 变体（不 claim NCM 数据接口、跳过 VpnService；由内核驱动持有 usb1 + 平台侧配地址），**已打通的 iAP2 控制通道完全复用**。
- Wi-Fi 混合方案保留为后备（两线不冲突）；纯无线（BT 引导）另起炉灶。
- 附加能力：系统应用安装（免签名约束）、日志/看护优化、蓝牙栈调试、tun.ko/内核模块补充。

## 5. 风险矩阵

| 路线 | 风险 | 处置 |
