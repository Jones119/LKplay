## 1. 逐条评估（按对 CS11 的价值排序）

### ① `593ac23` — Add experimental CarPlay audio over the car's Bluetooth ★★★（与我们的 A2DP 坑正面相关）

**它的做法**：新增一个默认关闭的高级设置，接到**已有的** `AirPlayConfig.disableAudioOutput` ——
**DiPlay 完全不向 iPhone 提供 CarPlay 音频**，于是音乐/导航/通话**留在 iPhone 与车机的 A2DP/HFP 链路上**，
由司机把车机音源切到"蓝牙"（作者原话：*as Carlinkit adapters do with `UseBluetoothAudio`*）。改动时重连 CarPlay；
会话日志记录开始时与 30 秒后的 A2DP/HFP 状态。作者在 **Leapmotor C10 + iPhone 15 Pro Max + Spotify** 上验证"不再断续"。

**为什么这条对我们重要**：它解释了"车机为什么会暂停手机"这个现象的**另一种回避方式**——不是像我们那样
**主动释放 A2DP**（让 CarPlay 承载音频），而是**干脆放弃 CarPlay 音频**、让车机把"蓝牙"当音源
（此时车机 `BTMusicPlaybackEngine` 判定的 `isBtAudio=true`，那条 `NotToPlay → AVRCP pause` 自然不触发）。

**两条路线对比**：

| | 我们（A2DP 释放看护器，`ec16265`） | 上游（`disableAudioOutput` + 车机 Bluetooth 音源） |
|---|---|---|
| CarPlay 音频集成 | ✅ 有（导航播报、Siri、通话都走 CarPlay，且我们补了 Opus 编解码） | ❌ 无（音频全在车机蓝牙链路上；通话走 HFP） |
| 依赖 | 车机厂商 API `Bt.create→getA2dp→reqA2dpDisconnect`（CS11 实测可用） | 只要司机把车机音源切到蓝牙；不需要厂商 API |
| 风险 | iOS 可能自行重连 A2DP（看护器每 5 秒兜一次） | 丢掉 CarPlay 音频能力（导航不压媒体、Siri 走 HFP） |
| 适用场景 | 我们已验证：**音乐恢复 + Siri + 通话双向**（平板同构环境） | 车机 BT 栈会疯狂抢回 A2DP、或厂商 API 不可用的车 |

**建议**：**保留我们的路线为默认**，把 `593ac23` 作为**可选的 Plan B** 移植（默认关闭、加一个设置项）。
它只有 `11 files, +57/−1`，代码量小、且是**附加**功能；但触及 `AirPlayPersistence` / `CarPlayHostActivity` /
`DiPlayActivity` / 7 语言 strings（**均被我们改过**）⇒ **必须人工移植（不要 cherry-pick 直接落）**。
