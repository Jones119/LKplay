# 30 · 平板验收清单（无需车机）

> 为什么要有这份清单：**平板（小米 Pad 6 Max 14 / Android 15）是一台完整的 CarPlay 接收端**，
> 除了"车机硬件相关项"，我们需要的验证几乎都能在平板上做——**不必点火、不费油、迭代快**。
> 2026-10-08 首夜就用它证明了「麦克风上行链路本身正确」（Siri 与高德语音导航都成功）。
> 车机专属项见文末 §5，仍按 `28-CS11上机验证清单（点火窗口）.md` 执行。

## 0. 环境与装包

```bash
adb devices -l                      # 平板序列号 5329c7f4（USB）
adb -s 5329c7f4 install -r CarPlay-CS11/mobile/build/outputs/apk/debug/mobile-debug.apk
adb -s 5329c7f4 shell am force-stop com.shihab.diplay.hudtest
adb -s 5329c7f4 shell monkey -p com.shihab.diplay.hudtest -c android.intent.category.LAUNCHER 1
# 采集（平板没有 busybox，用原生 logcat）
adb -s 5329c7f4 logcat -v time -s xcertplay-usb > tablet-run.log
```

**环境差异（重要）**：平板是 **arm64-v8a**，而自带的 `libdiplay_opus.so` 只有 armeabi-v7a →
平板上**不会**加载它，走的是 **Android 15 的 MediaCodec Opus**；车机（4.4）反过来走 **libopus**。
所以**两边都测**才能覆盖两条 Opus 路径。

## 1. 无线连接

按 doc 20 的流程让 iPhone 连上平板（平板开热点/P2P + BT 交握）。成功标志：CarPlay 画面出现在平板上，日志出现
`starting controller display=… microphone=true`。

## 2. 音乐（媒体音频）

Apple Music / QQ音乐 各播 20 秒。判读（`audio stats` 行）：

| 现象 | 判读 |
|---|---|
| `playing=true`、`playbackHeadFrames` 持续增长、`underruns=+0` | 正常 |
| 声音从**手机**出来、日志**完全没有** `audio stats` | iOS 没把音频送到我们（历史上出现过：音频格式里去掉 Opus 就会这样） |
| 播 1 秒就停（**车机专属**） | 车机 A2DP 暂停（见 doc 27 §6sexies-A），平板不会有 |

## 3. 麦克风：Siri 归属验证（**关键步骤，别省**）

1. 点 Siri 说一句（如"今天天气怎么样"），确认能听懂；
2. **把 iPhone 拿到另一个房间/远离平板**（或直接盖住手机麦克风），再说一次；
3. 结论：
   - **仍能听懂** ⇒ 用的是**平板（配件）麦克风** ✓，我们的上行被 iOS 采用；
   - **听不懂了** ⇒ 上一轮用的是**手机自己的麦克风**，本轮只证明代码链路、不证明"配件麦克风被采用"。

日志侧同时核对（证明链路在跑，但不能替代上面的人耳/距离实验）：

```
microphone probe source=6 rate=48000 result=1920      ← 探测通过（source 6 = VOICE_RECOGNITION）
Microphone: start … codec=OPUS rate=48000 channels=1 routedDeviceType=15   ← 15 = 内置麦克风
Microphone: stats … captureBytes>0 readErrors=0 encodedFrames>0 udpSent>0 sendErrors=0
```

## 4. 第三方 App 的语音（高德）

让 Siri 打开高德 → 用**高德内的语音**说目的地 → 应能开始导航（2026-10-08 已通过 ✓）。
失败时看是否有新的 `Microphone: start`（若根本没有，说明是 App/系统侧没请求我们的麦）。

## 5. 通话（**验证软件 Opus 解码器**）

用 CarPlay 打一个电话，**听对方的声音**是否从平板/车机出来。判读：

| 日志 | 含义 |
|---|---|
| `Audio: software Opus decoder active=true` | MediaCodec 没有 Opus 解码器，已回退 libopus ✓ |
| `decoderUnavailablePacketsTotal` 停止增长、`outputBuffersTotal` 增长 | **能听见对方** ✓ |
| `decoderUnavailablePacketsTotal` 持续增长 | 解码仍在丢（回退没生效，需查日志里的创建失败原因） |

## 6. 触控与性能指标

连续滑动 30~40 秒，读 `video stats`：

| 字段 | 期望 |
|---|---|
| `shownP50` / `shownP95` | 30fps ⇒ 33ms；p95 远大于 p50 才算"节奏不均" |
| `dropped` / `queueMax` | 0 或接近 0；持续 >0 说明下游跟不上 |
| `recoveries` | **必须 0**（>0 即肉眼可见卡死） |
| `touch2frame avg/max`、`touchQueueMax` | avg <100ms 理想；`touchQueueMax` 接近 200ms 整数倍 ⇒ 上行排队 |

## 7. 平板测不到、只能上车的项

1. **车机麦克风独占**（`AudioRecord.read` 返回 -3）——平板没有这问题；
   **已备好脚本**：`tools/cs11_release_mic.sh`（经 rootd 队列执行，默认循环 3 分钟强停 `com.baidu.che.codriver` 与 ecarx 语音服务）；在窗口内点 Siri/高德语音，看 app 日志 `microphone probe source=… result=N`：**非负即通**。若车机设置里能直接关"语音唤醒"，优先用那个（永久且干净）。
2. **A2DP 暂停**（车机蓝牙引擎策略）与我们的释放看护器；
3. **热点「关→自动开」路径**；车机重启自愈；
4. **系统级调优**（IRQ/RPS/绑核/动画缩放）与热、功耗表现；
5. **清晰度**：已结案（1080p 否决、保持 720p，见 doc 27 §6bis），无需再测。

## 8. 复现要点（本轮踩过的坑）

- 平板**没有 busybox**：脚本里别用 `busybox xxx`；
- 我们的 `libdiplay_opus.so` 只覆盖 **armeabi-v7a**：arm64 设备不会被加载（这是预期行为，回退到 MediaCodec）；
- 平板上**没有车机那套厂商 API**（`com.ecarx.xui.adaptapi…`）→ `PhoneMediaAudioWatchdog` 会打印
  `bt api class not on the classpath` 并安静退出 ✓（不影响其它功能）。
